CACox ES 敏感性分析可移动代码包
建立日期：2026-11-04
目标运行环境：Windows + NVIDIA GPU + CUDA

一、用途与当前范围

本包用于CACox ES限制人群敏感性重训，以及原CACox ES总体模型在MPA/GPA中的直接折外评价。按照用户修订的范围，本包不训练RCS-ridge或作为对照的普通Cox预测模型，也不包含它们的预测列或方法间比较；LASSO Cox仍保留为CACox流程中的变量筛选方法。原研究中的其他模型结果仍保留在原始研究目录，与本包的正式敏感性计算分开。

正式敏感性目标是五个分支各10次重复×5个外层折，合计250个分支－外层折。沿用原冻结患者分折，不重新划分测试患者。每个外层折只用其允许的开发分区执行预处理、变量筛选、内层选择和最终重训，外层测试结局不得用于选择或训练。

五个分支由原始数据独立定义：
complete_case：29个原候选变量均完整，488人、47例死亡。
egfr_observed：原始eGFR有记录，756人、102例死亡。
renal_observed：原始Renal_Involvement有记录，859人、98例死亡；有记录包括阴性或阳性。
known_subtype：原始Type已知，1110人、141例死亡，包含MPA、GPA及EGPA。
no_egpa：原始Type已知且为MPA或GPA，1017人、133例死亡；Type缺失不被视为非EGPA。

需要插补的分支使用20个真实插补输入view；完整病例不插补、只使用一个真实view。完整病例最终预测复制为20个标签仅用于和原总体模型的20个插补预测逐一配对，不代表20次独立完整病例训练。

二、Windows安装与启动入口

请先完整阅读同目录WINDOWS_START_HERE.txt，并使用其中的安装与运行命令、依赖清单和启动脚本。该文件由统一启动器维护，是Windows命令的唯一操作入口；本说明不重复另一套命令。需要可用的Python、R、与NVIDIA驱动兼容的CUDA版PyTorch，以及依赖清单中的Python/R包。不得仅凭安装成功推断GPU可用；先按入口文件完成设备、依赖及快速验证，再启动正式预算。

把整个包复制到目标机器的一个本地目录；路径可以改变，不需要保留原Mac绝对路径。启动器以包目录定位code和input，默认将生成文件写入run。可用CACOX_PORTABLE_ROOT指定包根、CACOX_RUN_ROOT指定输出根，CACOX_PYTHON与CACOX_RSCRIPT指定实际解释器；优先由统一启动器设置。不要把输出根设为input或code。

本包input含患者级研究数据及已保存预测，须按研究数据管理要求保存在获授权的本地设备及存储中；复制到目标电脑不是上传，不需要上传到任何在线服务。

三、原始输入和主要文件

input/raw_typed.rds：原始类型化研究数据，由数据准备模块携带；包含原始Type、患者研究编号及生存结局。
input/config.rds：原候选变量及配置。
input/main_oof_cacox.csv.gz：原总体CACox ES的已保存折外预测，仅有repeat_id、fold、imputation、patient_id、Death、Survival_Days、score_E_selected七列，共228000行。没有其他算法的预测，也没有为当前评价额外生成生存概率。
input/main_oof_cacox.csv.gz.sha256：该压缩文件的SHA256校验值。
code/evaluation.R：患者聚类C-index、配对协方差、Rubin合并和可移动输入读取函数。
code/subgroup_evaluation.R：原模型的总体、MPA和GPA折外评价，无重新拟合。
code/aggregate_sensitivity.R：五分支完整覆盖后汇总CACox ES重训结果。
code/portable_hash.py：跨平台输入和完成文件的完整性校验，由启动器配套维护。
code/verify_prediction.py：正式预测完成状态、生产配置、重放检查及SHA256清单验证。
run/branches/<分支>/repeatXX_foldYY/cacox_es/：每个外层折的模型、预测、完成标记及审计。
run/results/subgroup_original_oof/：原模型总体及MPA/GPA结果。
run/results/final_10x5_cacox_es/：全部250个分支－外层折完成后的正式汇总。
validation/：本包在制作机器上的数值复核记录；原OOF复核不能替代目标Windows设备的训练验证。

四、两类评价回答不同问题

MPA/GPA原模型亚组评价：直接读取原总体CACox ES的完整10×5×20折外预测，按照raw中的原始已知Type过滤。MPA为434人、71例死亡；GPA为583人、62例死亡。该步骤不重新筛选变量、不重新插补、不重新训练，也不根据亚组结局选择模型。它回答原总体模型在这些亚组中的区分度如何。

五分支敏感性主要比较：每个限制人群重训的CACox ES，与原总体流程的CACox ES，在完全相同的保留外层测试患者、repeat、fold和MI标签上配对。差值方向固定为重训后C减原模型C。不能用限制人群的C直接减原总体全部1140人的C来替代主要比较。

排除EGPA的专门比较：比较no_egpa与known_subtype两个重训流程，都仅在共同的1017名MPA/GPA测试患者上评价。两个开发集合均排除原始Type缺失；差值为no_egpa减known_subtype。这样不会把测试人群不同和Type缺失排除混入该配对比较。

另外保留亚组或限制人群与总体C的描述性病例构成差，不给这种跨人群差异附加推断性p值或CI，不把MPA/GPA不同的结果解释为正式交互作用检验。

五、统计方法及指标边界

本包评价仅包含Harrell C-index、相同患者上的配对C差及其95% CI。没有计算这些敏感性或亚组分析的时间依赖AUC、Brier/IBS、校准或DCA，不能将C-index结果写成全部预测性能均已验证。

使用survival::concordance(reverse=TRUE,timewt='n',influence=2)。只比较同一外层测试折内的可比较生存对，不跨不同拟合折排序风险分数。整体C是同折可比较对数加权的比率，不一定等于50个折C的简单平均。

每个插补编号内，将同一原始患者在不同重复中的比率影响函数贡献相加，再计算患者聚类的IJ方差和配对协方差。20个插补估计按Rubin合并，总方差为平均插补内方差加1.05倍插补间方差，并用相应t自由度形成区间及配对p值。重复出现的患者、20个标签和50个折都不视为独立新样本。

该推断以已拟合流程及冻结分折为条件，未完整纳入模型开发、选择和插补模型拟合的不确定性。属于同队列内部探索性分析，未作多重比较校正，不是独立外部验证。区间跨0不证明等效。

六、完成性、停止与恢复

正式汇总严格要求五分支全部50个外层折，不接受自动跳过失败折，也不以部分折结果冒充正式结果。每折读取预测前检查COMPLETE.json及其SHA256文件清单，再核对患者、分折、结局、20个标签和完整病例复制约束。缺文件、未完成、校验不符或成员不匹配均停止汇总。请以RUN_STATUS.txt中的成功状态判断一个汇总是否有效；存在CSV不等于汇总成功。

停止与恢复的准确命令、停止标记和队列选项见WINDOWS_START_HERE.txt。通过启动器请求安全停止，保留已经写入并校验完成的阶段；未完成阶段按原预算恢复或重算。不要手工补写COMPLETE.json、修改其哈希或拼接部分预测来绕过校验，也不要同时启动两个进程写入同一分支－折目录。

移机时可携带完整包、输入和通过来源校验的数据缓存；模型阶段恢复必须满足代码、数据、配置和设备签名。目标是CUDA重训，不能把Mac MPS或CPU阶段权重与CUDA阶段混合成同一套正式模型。换设备或改变科学配置时使用新的输出根并重新训练相关模型阶段，不通过修改签名继续旧模型。保持算法与计算预算不等于不同设备逐位产生相同随机权重或预测。

七、数值验证

subgroup_evaluation.R的验证模式重算原总体及MPA/GPA的C、SE、95% CI和Rubin方差分量，并与独立核对过的参考汇总比较。总体C应为0.749726596296937，MPA为0.693895330418805，GPA为0.774579367625566。

验证还检查相同预测的配对差与差方差为0，重复相同患者的额外预测不人为缩小患者聚类方差，并拒绝同一repeat/MI中的重复患者以及缺失折。验证只报告汇总数值，不打印患者级记录。具体通过项和误差保存在validation的CSV及TXT中。训练设备及保存权重重放的验证由统一入口另行执行。
